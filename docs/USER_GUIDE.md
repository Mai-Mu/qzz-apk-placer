# 使用指南

## 准备

- 一台 Windows 电脑。
- 一台能通过 Windows 资源管理器访问内部存储的 Android PDA。
- 支持数据传输的 USB 线。
- 保存在电脑上的有效、非空 `.apk` 文件。

程序适合依次给多台 PDA 交付同一个 APK。一次只连接一台目标设备。

## 首次使用

从 [Releases](https://github.com/Mai-Mu/qzz-apk-placer/releases) 下载 Windows x64 ZIP，解压后运行 `QzzApkPlacer.exe`。整个程序文件夹应保留完整，尤其是 `_internal`。

点击「选择 APK」，选中安装包。程序会保存路径，下次启动自动读取。随后连接 PDA，解锁设备并选择 USB「文件传输 / MTP」模式。

传输完成后界面显示「APK 已送达」。在 PDA 的内部存储 `Download` 文件夹找到安装包，手动打开并按设备提示安装。然后可以拔下设备，接入下一台。

## 日常操作

| 操作 | 效果 |
| --- | --- |
| 更换 APK | 保存新路径；若设备已连接且未手动暂停，立即传输 |
| 立即传输 | 对当前连接的设备重新传送当前 APK |
| 暂停自动传输 | 不开始新任务，正在进行的任务会先完成 |
| 恢复自动传输 | 恢复等待接入，或执行尚未完成的任务 |
| 关闭主窗口 | 收进系统托盘，继续后台运行 |
| 单击托盘图标 | 恢复主窗口 |
| 托盘菜单「退出程序」 | 请求取消并等待设备操作结束，再退出 |
| 再次运行程序 | 唤回已有窗口 |
| 传输记录 | 展开本次运行最近的设备与传输记录 |

## 路径失效时

APK 被删除、移动、变为空文件或无法读取时，程序暂停自动传输。即使原路径后来重新出现，也需要点击「更换 APK」重新选择一次。

重新选中有效文件后，若 PDA 仍连接且未手动暂停，立即传输。若已手动暂停，需要再点击「恢复自动传输」。

## 覆盖与文件更新

目标目录为内部存储的 `Download`；目录不存在时程序尝试创建。仅覆盖与当前 APK 同名的文件，不清理其他名称的旧版本。

覆盖采用先删除目标同名文件、再写入新文件的方式。请等待成功提示再拔线；中途断开可能导致目标旧文件已删除或新文件未完整写入，程序会在设备可访问后重试。

源文件在同一路径更新不会触发自动重传；更新完成后点击「立即传输」，或重新选择该文件。

完成判定为设备写入提交成功且目标文件大小一致。程序日常传输不进行完整 SHA-256 读回；开发验证中单独执行过读回校验。

## 排错

| 状态或问题 | 处理方法 |
| --- | --- |
| 一直等待 PDA | 检查数据线、设备解锁状态、USB 模式，确认资源管理器能打开内部存储 |
| 传输失败 | 保持设备解锁，检查 USB 接触与存储空间，等待自动重试或点击立即传输 |
| 提示只连接一台 PDA | 拔下其他 USB 便携设备，只保留目标设备 |
| 内部存储无法唯一识别 | 先确认设备权限和驱动；程序不会自动改投 SD 卡 |
| 同名对象是文件夹 | 在设备上处理同名文件夹后重试；程序不会删除该文件夹 |
| 启动失败 | 查看启动异常记录，解压完整压缩包后重试 |

Windows 发布程序未签名。如果系统提示来源未知，请核对下载来源和 Release 附件中的 SHA-256 校验值。

## 设置与日志

数据目录：`%LOCALAPPDATA%\QzzApkPlacer\`。

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 最近选择的 APK 路径 |
| `app.log`、滚动备份 | 运行状态及异常信息 |
| `startup-error.log` | 启动发生异常时的记录；历史文件可能保留 |

向 [Issues](https://github.com/Mai-Mu/qzz-apk-placer/issues) 反馈时，提供系统版本、PDA 型号、发生步骤和相关日志。请先移除客户文件名、本地路径等不需要公开的信息。
